Overview

Robot development usually relies on separate descriptions of the robot's structure, its environment, its behavior and how it is evaluated, and the developer keeps them consistent by hand. RobotDSL is a family of domain-specific languages in which one program describes all four, and a compiler assembles the robot, derives its dependent settings and checks the whole system before anything runs.

MobileDSL, for mobile robots, is the first language of the family. MobileCopilot is an agentic framework that uses MobileDSL and its compiler as tools: given a request, a coding agent retrieves components, writes a program and refines the design using compiler feedback. On a benchmark of 50 mobile robot design tasks, this raises the share of systems that complete their programmed behavior in simulation by 42–50 percentage points over direct authoring of ROS/Gazebo files, while cutting API cost by about 33–61%.

MobileDSL

MobileDSL represents a mobile robot and its operation as one program composed of four language modules. Shared names connect them, so changing a goal updates both the generated task coordinates and its distance check.

CoreDSL

The robot

An assembly of reusable components with functional roles (chassis, wheels, sensors, attachments) joined through mating connectors.

WorldDSL

The environment

Obstacles, the initial pose and named goals such as @world/door.

TaskDSL

The behavior

A tree of Nav2 actions that refers to the world's goals by name.

EvaluateDSL

The checks

Which quantities are observed and which bounds must hold during a run.

The compiler resolves references, checks compatibility and derives assembly transforms and dependent settings such as the controller geometry and the navigation footprint. A backend then translates the result into files for the target execution environment.

CoreDSL: a mecanum robot with a lidar and an arm (paper, Listing 1)
Robot nav_bot {
  Mecanum_four_wheel chassis(ref="silver"),
  Mecanum wheel_lf(ref="red", glue="0.0976 0.095 -0.0443 0 1 0"),
  Mecanum wheel_lb(ref="red", glue="-0.1124 0.095 -0.0443 0 1 0"),
  Mecanum wheel_rf(ref="red", glue="0.0976 -0.095 -0.0443 0 -1 0"),
  Mecanum wheel_rb(ref="red", glue="-0.1124 -0.095 -0.0443 0 -1 0"),
  Lidar front_scan(ref="lidar", glue="0.11 -0.0001 -0.0043 0 0 -1"),
  Arm top_arm(ref="arm", glue="-0.0073 -0.0001 -0.0043 0 0 -1")
}
// compiles to URDF, controller, Nav2 footprint, Gazebo world, behavior tree and checks

MobileCopilot

MobileCopilot couples an LLM coding agent with the MobileDSL compiler. The agent searches the component library with text or images, writes the four language modules and compiles. The compiler returns diagnostics that identify a violated constraint and, where available, the source location or a suggested correction; the agent edits the program and recompiles. Successful compilation produces the robot and world models, controller and navigation settings, a behavior tree and an evaluation plan for the selected target.

Results

Agents that author MobileDSL programs are compared with the same agents authoring ROS/Gazebo files directly, on 50 mobile robot design tasks, under the same budget, component library and execution environment. Motion response is whether the generated robot moves in simulation; system execution is whether the system completes the behavior defined in its own program. System execution success increases by 42–50 percentage points, authored code decreases about 12–28 times and API cost by 33–61%.

Which module contributes most?

Replacing one module at a time with its conventional file equivalent (Codex, gpt-5.6-sol) shows that CoreDSL contributes most: removing it reduces system execution success from 74% to 36% and increases authored code more than sevenfold. In a separate single-response comparison with fixed components, CoreDSL needs about 28–37 times less code than URDF or Xacro.

Next languages

In design

MobileDSL is the first member of the family. Languages for manipulation and legged platforms are in design; the compiler's component model is built to be shared across them.

RobotDSL roadmap
  1. CompleteMobileDSL 1.0: the four modules, the compiler, the component library and the benchmark examples behind the paper's results. The compiler will be offered as a hosted service; its sources are not public.
  2. In developmentMobileCopilot Studio with your own API key (preview online), component uploads with review, and “report issue” on generated designs.
  3. OpenPublic discussions and issues for questions, shared designs, announcements and feedback.
  4. PlannedA documentation site and simulation runs in the browser.
